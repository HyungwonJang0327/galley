### 판단(에이전트)

- **시작 단계 기본값은 pipeline이 정한다**(`resolveStartStep`) — `applyCommand`는 상태 전이만 알고 단계 행을 모르므로, 단계를 아는 `reviseRun`·`previewRerun`이 같은 함수로 기본값·거절을 맞춘다. 미리보기가 "상태를 보지 않는다"던 원칙에 예외 하나(확인 Dialog가 실제 계획을 보여야 해서).
- **실패에서는 키워드 자동 규칙을 쓰지 않는다** — 지시에 "커밋"이 있어도 실패 단계가 기본. 자동 규칙은 "본문을 고칠 때 근거까지 다시 볼지"의 규칙이라 실패 복구와 맞지 않는다.
- 화면의 "뒤 단계 비활성"은 보조 — 서버 가드가 진실. Select 항목 `disabled`는 Base UI 옵션 `aria-disabled`로 테스트.
- `NOT_PENDING_APPROVAL` 코드는 그대로 두고 문구만 "승인 대기 또는 실패"로 — 코드 이름을 바꾸면 라우트·테스트가 흔들리고 뜻("손댈 수 있는 상태가 아님")은 같다. 기록만.
- 실패 Run의 `workerId`는 비운다(기존 updateMany 그대로) — 실패 종결 시 이미 null이라 무해.
