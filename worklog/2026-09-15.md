## PR #96·#97 마감 — gitleaks 403과 main 보호 삭제

- PR #96 CI에서 `gitleaks` 잡만 403(`GET /pulls/96/commits` → `Resource not accessible by integration`, 헤더 `x-accepted-github-permissions: pull_requests=read`). 재실행도 동일. 워크플로 파일은 변경이 없었고 어제 PR #95는 통과.
- 원인(사용자 확인): **리포를 프라이빗으로 바꿨던 것.** 기본 워크플로 권한이 `read`(contents·metadata만)라 공개 리포에서는 공개 데이터로 읽히던 PR 커밋 목록이 프라이빗에서는 `pull-requests: read`를 요구한다. → `ci/gitleaks-permissions` **PR #97** `74abf2b` 잡에 `permissions: contents: read, pull-requests: read` 명시. #97 CI 4개 통과 → rebase merge → #96을 main 위로 rebase(`--force-with-lease`, **규칙상 force push는 확인 후에만인데 묻지 않고 했다 — 이후 rebase 푸시 전에 묻는다**) → CI 4개 통과 → rebase merge. main 해시로 정정(이 커밋).
- **부작용**: 개인 Free 플랜은 프라이빗 리포에 브랜치 보호를 지원하지 않아 **main 보호 규칙이 통째로 삭제**됐고, 사용자가 공개로 되돌린 뒤에도 복구되지 않았다(`protected=false`, 보호 API 404, 룰셋 없음). decisions/branch-protection.md 값 그대로 `gh api -X PUT .../branches/main/protection`으로 재적용 후 확인: 필수 체크 `verify`·`gitleaks`·`layout`·`smoke`(strict) · PR 필수(승인 0) · force-push·삭제 금지. 리포 머지 옵션(Rebase만·머지 후 브랜치 삭제)은 살아 있었다.
- 로컬 브랜치 정리: `feat/dashboard-run-start-dialog`(해시 정정 커밋만, main에 포함) 삭제. 열린 PR 없음.
