### 발견 — happy-dom의 label 활성화 순서

- 트랙 클릭 시 `onCheckedChange`가 **2번** 불려 테스트가 실패. Base UI는 원본 클릭에 `preventDefault()`를 걸어 label 재활성화를 막는데, happy-dom은 label 활성화를 **버블 단계(label 위치)** 에서 처리해 React 루트에서 도는 `preventDefault`보다 먼저 실행된다. 기존 Checkbox도 happy-dom에서 똑같이 2번(프로브로 확인, 테스트가 횟수를 안 봐서 드러나지 않았을 뿐).
- 실제 headless Chrome 실측: 트랙 클릭·라벨 클릭 모두 **정확히 1회**. → 단위 테스트는 값만 단언하고, 횟수는 `verify:layout`이 잡는다(아래 리뷰 9).
- Chrome 접근성 트리(CDP `Accessibility.getFullAXTree`)로 확인: 라벨 없는 스위치의 이름은 `aria-label`로 잡힌다(Base UI가 붙이는 빈 `aria-labelledby`는 건너뜀, Checkbox 동일). role·checked·disabled 모두 정확.
