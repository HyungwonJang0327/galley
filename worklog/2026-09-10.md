### CI 1차 실패 → 스크립트 fix (`164467e`)

- **증상**: PR #45 1차 CI에서 `verify`·`gitleaks` 초록, **`layout` 실패(1m4s)**. 빌드는 성공, 실측 뒤 `ENOTEMPTY: directory not empty, rmdir '/tmp/galley-cdp-…/Default'` 한 줄만 찍고 exit 1(PASS/FAIL 목록 없음).
- **원인**(systematic-debugging): `cdp.mjs` `close()`의 `rmSync(profile, {recursive, force})`가 재시도 없이(`maxRetries` 기본 0) 프로필을 지우는데, Linux에서는 브라우저 프로세스 exit 뒤에도 자식(GPU·네트워크 등)이 `Default/`에 잠깐 써서 readdir→unlink→rmdir 사이에 새 항목이 생겨 ENOTEMPTY. macOS 로컬 10회+에서는 한 번도 안 남. 이 예외가 `run.mjs`의 `finally`에서 던져져 **결과 출력 전에 죽고**, `launchChrome`의 catch→`close()` 경로에서는 **원래 오류를 가린다**(Chrome 기동 실패였어도 ENOTEMPTY만 보였을 것).
- **수정**: `removeDir(dir)`로 분리 — `rmSync(..., {maxRetries: 5, retryDelay: 200})` + 실패는 `console.warn`만(임시 폴더 잔존은 실측 결과와 무관). Puppeteer가 user-data-dir 정리에 쓰는 것과 같은 방식. 러너 특화 Chrome 플래그(`--no-sandbox` 등)는 넣지 않음 — 증거 없음.
- **테스트(RED→GREEN)**: `scripts/verify-layout/cdp.test.mjs`(`@vitest-environment node`, vitest 기본 include가 `scripts/**/*.test.mjs`를 잡음) — 보통 폴더 삭제 / 하위 폴더 `chmod 555`로 unlink 불가하게 만든 뒤 던지지 않고 warn 1회(root·win32 skip). 미구현 상태 2 FAIL → 구현 후 dashboard 6 통과. 경합 자체는 결정적으로 재현 불가라 "정리 실패가 전파되지 않는다"만 검증. 로컬 `--no-build` 68/68 유지. lint·prettier 통과.
