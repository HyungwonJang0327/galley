## P7d Pagination (feat/ui-pagination)

참여: 사용자(승인) · 메인 에이전트(구현).

- `Pagination`(components): 제어형 `page`(1부터)/`pageCount`/`onPageChange`, `siblingCount`·`boundaryCount`, `showFirstLast`, `disabled`, `labels`(기본 영어 — 한국어 앱은 넘긴다), `aria-label`. 마크업 `<nav aria-label>` 안 `ul>li>button`, 현재만 `aria-current="page"`, 생략 `…`은 aria-hidden, 이전·다음은 양끝에서 disabled, 현재 쪽 클릭은 콜백 안 부름, 범위 밖 page는 안쪽으로. 현재 쪽은 primary 버튼과 같은 채움(accent + accent-fg). `paginationRange` 순수 함수 export — 처음·현재±sibling·끝, 2칸 이상 비면 생략·딱 1칸이면 숫자, 양끝에서 항목 수가 같다(폭 고정). 라우터를 모른다(앱이 onPageChange에서 URL로).
- 잡은 것 둘: (1) 서버 page.tsx(갤러리)에서 `onPageChange={() => {}}` **함수 prop을 클라이언트 컴포넌트에 넘겨** /design 전체가 깨졌다(실측 16/42) — 상태·함수가 필요한 데모는 PrimitiveDemos(클라)로. 처음엔 `'use client'` 누락으로 오판해 배너를 붙였는데, 번들 배너(UM1)로 galley-ui 전부가 이미 클라이언트라 무관했다 — 마감 브랜치에서 RF-28 규칙대로 배너를 뺐다(훅·Base UI 없는 파일엔 두지 않는다). (2) 실측에서 현재 쪽 색이 accent의 98% 중간값 — `--ui-duration-fast` 120ms 전환이 100ms 대기보다 길다. 모듈이 `getAnimations({subtree:true})` 끝까지 기다린 뒤 읽게 했다(색 전환 있는 요소를 재는 첫 모듈).
- 검증: ui 352(+8) · dashboard 426 · lint·typecheck · ui build · verify:layout 261/261(+10). changeset minor `ui-pagination.md`(0.3.0 후보). README en·ko·ja.
- 실제 화면 자리는 아직 없다(큐·이력은 전체 목록) — 라이브러리 채우기. 자리가 생기면 URL `?page=`에 두고 onPageChange에서 router.push.
