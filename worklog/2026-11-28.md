- 입력 위치: **큐 행 ⋮ 메뉴에 새 항목 "배경 메모"**. 기각 — 근거 편집 Dialog 안(Dialog가 길어짐), 실행 시작 Dialog 안(미리 적어 두기 불편).
- 저장 위치: **DB에만**. 기각 — `주제_큐.md`에도 쓰기(파서·쓰기 규칙·결정 문서를 함께 바꿔야 해서 단위가 커짐).

### 구현

- `b77b874` feat(pipeline): `QueueItem.backgroundNote`(마이그레이션 `20261128120000_queue_item_background_note`) · `queue/topicNote.ts`의 `getTopicNote`·`setTopicNote`(줄바꿈 정리, 앞뒤 공백 제거, 비면 null, 상한 2,000자, 같은 값은 쓰지 않음). 재적재 뒤에도 메모가 남는 것을 테스트로 고정.

### 판단(에이전트)

- 메모에도 식별 정보 필터를 건다. 사람이 쓴 글이지만 회사 이름·도메인이 적힐 수 있고, 커밋 메시지·작업 문서와 같은 규칙으로 두는 편이 설명하기 쉽다.
- posts 사본에는 메모의 길이만 남긴다. 메모에는 포인터(커밋·경로)가 없어 "있었다"는 사실만 남는다.
- 고정 머리의 한 줄은 메모가 있을 때만 붙인다 — 메모가 없는 실행의 프롬프트가 달라지지 않아 지난 실행과 비교가 깨지지 않는다.
- 근거 검증(판정 프롬프트·숫자 대조)은 아직 메모를 보지 않는다. 이력·문서와 같은 문제(근거에 있는데 검증이 못 봄)라 단위 3에서 한꺼번에 넣는다. 그 전에 메모를 쓴 실행은 메모에서 온 숫자가 `unsupported`로 표시될 수 있다.
- 큐 목록 행에는 메모가 있는지 표시하지 않는다(요청 범위 밖). 저장해도 목록을 다시 그리지 않는다.

- 머지: PR #212. 로컬 DB에 마이그레이션 적용(`pnpm --filter @galley/pipeline db migrate deploy`). 에이전트가 처음에 `exec prisma migrate deploy`를 안내해 사용자가 한 번 실패했다(`.env`가 루트에만 있어 `DATABASE_URL`을 못 읽는다 — 2026-09-25에도 같은 실수).

### 판단(에이전트)

- 서술 규칙은 층이 있을 때만 붙인다. 날짜가 없는 옛 묶음에 "타임라인 4개 이상"을 요구하면 지어내게 된다. 같은 이유로 "근거에 그보다 적으면 있는 만큼만"을 넣었다.
- 기록에서 찾은 숫자는 포인터 없이 사유 코드만 남긴다. `evidenceRef`는 조각(커밋·경로·줄)을 가리키는 형식이라 메모·문서에 맞지 않는다.
- 클린룸 검사는 그대로 코드 조각만 본다.
- 비용: 8차 실측(본문 입력 13,134 · 검증 입력 63,610토큰, 실행 0.97달러)에서 계산하면 입력 단가 약 5달러/100만 토큰. 묶음이 약 3만 자 늘면 검증이 판정 묶음(5회 안팎)마다 다시 보내 가장 많이 는다. 추정 실행당 약 1.6달러 — 9차에서 실측한다.
