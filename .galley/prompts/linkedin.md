# 링크드인 요약본 어투

[어투 공통 규칙]
- 사실만 쓴다. 근거 없는 수치·이유·에피소드는 넣지 않고 `<!-- [확인 필요] ... -->` HTML 주석으로 남긴다.
- 이모지 없음. 제목·본문·헤더 모두.
- 대표·동료 개인에 대한 감정적 서술, 회사 비난 톤 없음. 회사는 "회사에서 운영하던 서비스" 정도로만 지칭.
- 회사 코드는 그대로 싣지 않는다. 구조만 살려 클린룸으로 다시 쓴 예시 코드. 실제 키·MID·도메인·회사명·법인명·고객 안내 문구 금지. 회사 고유 API 경로·라우트·쿼리 파라미터·응답 필드명은 일반 이름으로 바꾼다(`/internal/pay/nice/callback` → `/payments/nice/return`, `ordsess` → `session`). 공개 SDK/문서에 있는 이름은 그대로 써도 된다.
- 잘한 것과 아쉬운 것을 같은 무게로 쓴다. 삽질은 숨기지 않는다.
- 문장은 짧게. 한 문단에 한 가지. 접속사로 문장을 늘리지 않는다.
- "정말", "진짜", "너무", "굉장히" 같은 강조 부사 없음. 숫자로 말한다.

[어투: 링크드인]
- 훅은 내 사건 한 줄. "어느 날 갑자기 결제가 멈췄습니다." 뉴스형 훅("요즘 ~가 화제입니다") 금지.
- 존댓말 -습니다체, 담백하게. 마침표 생략·"ㅎㅎ"·느낌표 없음.
- 이모지·숫자 이모지·해시태그 없음. 번호는 플레인 "1. 2. 3.".
- 구조: 사건 1~2문단 → 조건(숫자로: 스토어 50개, 월 주문 1,000건, 프론트 혼자) → "그때 내린 결정은 세 가지입니다." → 1. 2. 3. (각 3~4문장) → 결과 한 문단 → 삽질 한 문단("삽질도 있었습니다.") → 핵심 통찰 한 문장 + 짧은 덧붙임 한 문장.
- 마지막 줄은 `글: [벨로그 링크]`.
- 1,000~1,300자.
- 자기 홍보 문장("~에 관심 있으시면 연락 주세요") 없음. 글이 대신 말하게 둔다.

예시 톤:
"PG 전환은 SDK 교체가 아니라 결제 요청, 결과 수신, 결제수단, 결과 화면이라는 네 경계를 어디에 세울지 정하는 일이었습니다. 코드보다 경계가 먼저였습니다."

[참고 완성본 — 아래 글과 같은 결로 쓴다. 주제·내용·수치는 따라 하지 않고 문체·리듬·문단 길이·헤더 구조만 따른다]

어느 날 갑자기 결제가 멈췄습니다. 배포한 것도 없었습니다.

PG사 쪽에서 우리 서비스 결제를 중단한 거였고, 저희는 그걸 고객 문의로 처음 알았습니다. 계약서에 불리한 조항이 있었고 그게 그대로 실행된 날이었습니다. 그날 할 수 있었던 건 결제 오류 안내를 띄우는 핫픽스뿐이었습니다.

이 사건으로 Toss Payments에서 NicePay로 PG를 옮기게 됐습니다. 인플루언서 스토어 50여 개, 월 주문 1,000건, 몰마다 전환 시점이 다르고, 결제는 한 순간도 멈추면 안 되는 조건이었습니다. 프론트엔드는 저 혼자였습니다.

그때 내린 결정은 세 가지입니다.

1. 전환 스위치를 프론트가 아니라 서버에 뒀습니다. 어느 PG를 쓸지를 빌드나 환경변수가 아닌 몰 정보 API의 pgType 필드로 받았습니다. 프론트 배포와 PG 전환 시점이 분리됐고, 몰 하나만 먼저 바꿔 실결제를 검증하는 것도 값 하나로 끝났습니다.

2. 두 PG의 SDK를 동시에 로드하고 분기는 한 곳에만 뒀습니다. Toss는 JS SDK와 리다이렉트, NicePay는 SHA-256 서명이 들어간 폼 POST에 EUC-KR. 방식이 완전히 다른데도 결제 요청 함수 하나에 차이를 가두고, 주문서·배송지·포인트·약관은 PG를 모르게 했습니다.

3. 결과 페이지는 PG를 모르게, 백엔드가 파라미터를 통일했습니다. 어느 PG든 승인이 끝나면 같은 쿼리 파라미터로 결과 페이지에 보내주기로 합의했습니다. 프론트에 남은 분기는 가상계좌 예금주 표시 한 줄이었습니다.

양쪽이 켜진 상태로 한 번 배포한 뒤, 몰별 전환은 전부 백엔드 값 변경으로 끝났습니다. 4월에 시작해 6월 말에 전환을 시작했고, 그 사이 프론트 재배포도 결제 중단도 없었습니다.

삽질도 있었습니다. 계약상 정해진 연동 모듈을 확인하지 않고 신형 SDK로 먼저 붙였다가 갈아엎은 것, 서명 키를 코드에 하드코딩했다가 환경변수로 옮긴 것, 앱 웹뷰에서 crypto.subtle이 없어서 낸 핫픽스. 글에는 이 부분도 그대로 적었습니다.

PG 전환은 SDK 교체가 아니라 결제 요청, 결과 수신, 결제수단, 결과 화면이라는 네 경계를 어디에 세울지 정하는 일이었습니다. 코드보다 경계가 먼저였습니다.

글: [벨로그 링크]
