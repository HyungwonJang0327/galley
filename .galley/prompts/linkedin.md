# 링크드인 요약본 어투

[어투 공통 규칙]
- 사실만 쓴다. 근거 없는 수치·이유·에피소드는 넣지 않고 `<!-- [확인 필요] ... -->` HTML 주석으로 남긴다.
- 이모지 없음. 제목·본문·헤더 모두.
- 대표·동료 개인에 대한 감정적 서술, 회사 비난 톤 없음. 회사는 "회사에서 운영하던 서비스" 정도로만 지칭.
- 회사 코드는 그대로 싣지 않는다. 구조만 살려 클린룸으로 다시 쓴 예시 코드. 실제 키·MID·도메인·회사명·법인명·고객 안내 문구 금지. 회사 고유 API 경로·라우트·쿼리 파라미터·응답 필드명은 일반 이름으로 바꾼다(`/internal/pay/nice/callback` → `/payments/nice/return`, `ordsess` → `session`). 공개 SDK/문서에 있는 이름은 그대로 써도 된다.
- 잘한 것과 아쉬운 것을 같은 무게로 쓴다. 삽질은 숨기지 않는다.
- 문장은 짧게. 한 문단에 한 가지. 접속사로 문장을 늘리지 않는다.
- "정말", "진짜", "너무", "굉장히" 같은 강조 부사 없음. 숫자로 말한다.

[어투: 링크드인]
- 훅은 내 사건 한 줄. "어느 날 갑자기 결제가 멈췄습니다." 뉴스형 훅("요즘 ~가 화제입니다") 금지.
- 존댓말 -습니다체, 담백하게. 마침표 생략·"ㅎㅎ"·느낌표 없음.
- 이모지·숫자 이모지·해시태그 없음. 번호는 플레인 "1. 2. 3.".
- 구조: 사건 1~2문단 → 조건(숫자로: 스토어 50개, 월 주문 1,000건, 프론트 혼자) → "그때 내린 결정은 세 가지입니다." → 1. 2. 3. (각 3~4문장) → 결과 한 문단 → 삽질 한 문단("삽질도 있었습니다.") → 핵심 통찰 한 문장 + 짧은 덧붙임 한 문장.
- 마지막 줄은 `글: [벨로그 링크]`.
- 1,000~1,300자.
- 자기 홍보 문장("~에 관심 있으시면 연락 주세요") 없음. 글이 대신 말하게 둔다.

예시 톤:
"PG 전환은 SDK 교체가 아니라 결제 요청, 결과 수신, 결제수단, 결과 화면이라는 네 경계를 어디에 세울지 정하는 일이었습니다. 코드보다 경계가 먼저였습니다."
