# Zenn 日本語版のトーン

[어투 공통 규칙]
- 사실만 쓴다. 근거 없는 수치·이유·에피소드는 넣지 않고 `<!-- [확인 필요] ... -->` HTML 주석으로 남긴다.
- 이모지 없음. 제목·본문·헤더 모두.
- 대표·동료 개인에 대한 감정적 서술, 회사 비난 톤 없음. 회사는 "회사에서 운영하던 서비스" 정도로만 지칭.
- 회사 코드는 그대로 싣지 않는다. 구조만 살려 클린룸으로 다시 쓴 예시 코드. 실제 키·MID·도메인·회사명·법인명·고객 안내 문구 금지. 회사 고유 API 경로·라우트·쿼리 파라미터·응답 필드명은 일반 이름으로 바꾼다(`/internal/pay/nice/callback` → `/payments/nice/return`, `ordsess` → `session`). 공개 SDK/문서에 있는 이름은 그대로 써도 된다.
- 잘한 것과 아쉬운 것을 같은 무게로 쓴다. 삽질은 숨기지 않는다.
- 문장은 짧게. 한 문단에 한 가지. 접속사로 문장을 늘리지 않는다.
- "정말", "진짜", "너무", "굉장히" 같은 강조 부사 없음. 숫자로 말한다.

[어투: Zenn]
- です・ます調の技術記事。挨拶・自己紹介なし。絶制されたトーン、本文に絵文字なし。
- 첫 줄 `# タイトル`. 「〜した話」「〜する前に〜した話」꼴. 부제는 「—」로.
- 「## はじめに」로 시작: 무엇을, 어떤 조건에서, 왜 썼는지 3~4문장. 「## まとめ」로 끝: 요점 2~4개 불릿 + 한 문장 소감.
- 구조는 벨로그판과 같다: 사건/배경 → なぜ単純な置き換えではだめか → ## 1. 2. 3. → ## つまずいたところ → ## 結果 → ## まとめ.
- 코드·표는 벨로그판 그대로, 주석·label만 일본어.
- 일본 독자용 보충: PG=決済代行会社, 한국 서비스명은 일본 유사 서비스에 빗대 한 줄(Toss Payments・NicePay → GMOペイメントゲートウェイやSBペイメントサービスのような決済代行会社). 공구=共同購入, 인플루언서 몰=インフルエンサー向けストア 등 풀어 쓴다.
- 실명·회사·법인명·개인명·GitHub·앱스토어 링크 없음. 닉네임은 エディ만. 프로젝트명도 일반명사로(楽曲クイズアプリ, ウィッシュリスト共有サービス).
- 삽화 자리는 `<!-- [挿絵] illustN_....png — 日本語キャプション版は別途 -->`.
- 마지막에 구분선 뒤 「韓国語版（コード多め）はこちら：[velogリンク]」.
- 2,500~4,000자(코드 제외).

例のトーン:
"前職の韓国ECスタートアップで、決済代行会社（PG）を止めずに乗り換える作業を担当しました。フロントエンドは私1人、企画担当はおらず、要件は代表から直接受け取る体制でした。"
