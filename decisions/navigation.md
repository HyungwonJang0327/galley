# 네비게이션 IA (사이드바·TopBar)

사이드바 메뉴 구성·순서와 TopBar 구성을 정한다. 화면별 레이아웃은 → decisions/layout.md §3~§4.

## 결정

사이드바를 "정보 종류별 분류"에서 **글 하나의 생애주기(사용 흐름) 순서**로 재구성한다. TopBar 워크스페이스 탭(글/설정)을 제거하고 **워크스페이스 개념 자체를 없앤다**.

### 사용 흐름 (메뉴가 따르는 한 줄)

주제 모으기(후보) → 골라서 순서 정하기(대기) → 실행 → 검수(승인 대기 → 수정 지시 → 승인) → 발행(Zenn 下書き push · velog/LinkedIn 수동 복사) → 완료

- 가장 자주 여는 화면: **큐**, **승인 대기(실행)**.
- 가장 중요한 액션: **"승인 대기 n건"**.

### 사이드바 (위→아래 = 생애주기 = 사용 빈도)

| 그룹 | 항목                   | 경로              | 배지               | Phase          |
| ---- | ---------------------- | ----------------- | ------------------ | -------------- |
| 주제 | 큐                     | /queue            | 대기 n             | 1              |
| 실행 | 실행                   | /runs             | 승인 대기 n (주황) | 1              |
| 실행 | 이력                   | /runs/history     | —                  | 2 (빈 페이지)  |
| 발행 | 발행 대기              | /publish          | 미발행 n           | 2 (빈 페이지)  |
| 설정 | 리포 연결              | /settings/repos   | —                  | 2              |
| 설정 | 모델·비용              | /settings/model   | —                  | 2              |
| 설정 | 어투 프롬프트          | /settings/prompts | —                  | 2              |
| 외부 | Zenn 열기 · velog 열기 | (외부 링크)       | —                  | —              |
| 개발 | 컴포넌트 갤러리        | /design           | —                  | dev 전용(기존) |

- 활성 판정 URL(pathname). 상태(대기/후보/보류/완료·진행중/완료 등)는 **메뉴가 아니라 화면 안 탭(?tab=)**.
- 큐·실행·발행이 흐름의 3막. 이력·설정은 참조/보조.
- 개발 그룹(/design)은 `NODE_ENV==='development'`에서만 노출(기존 유지, 건드리지 않음).

### TopBar

- `[☰ 햄버거] Galley … [상태 칩(모델명 ▾)]` 만 남긴다.
- 워크스페이스 탭(글/설정) 제거. 설정은 사이드바 "설정" 그룹으로만 진입.
- 워크스페이스 개념은 TopBar.tsx에만 존재(별도 라우트 그룹·상태·컨텍스트 없음) → 제거 범위가 TopBar에 국한.

### 제거되는 라우트 → redirect

/queue/candidates · /queue/done · /runs/active · /publish/zenn · /publish/velog → 각각 새 경로로 redirect(구 링크 유입 대비).

- candidates · done → /queue (해당 상태는 ?tab=)
- runs/active → /runs
- publish/zenn · publish/velog → /publish

> redirect 구현 방식 = **next.config redirects**(선언적, 서버단 308). 배지 카운트 데이터 소스 = **사이드바 서버 컴포넌트에서 pipeline 함수 직접 조회**(별도 엔드포인트 없음, 갱신은 네비게이션 시점). 마크다운 렌더러(실행 상세 산출물 미리보기) = **react-markdown**, 위치 **apps/dashboard**(@galley/ui 도메인 무지·독립 배포 유지). — 2026-09-08 확정.

### 루트 진입

루트 `page.tsx`: 승인 대기 실행 ≥1건 → /runs, 아니면 /queue. **홈 화면은 만들지 않는다.**

## 이유

- 실제 작업은 "글 하나를 후보→발행까지 미는" 선형 흐름. 메뉴가 흐름을 그대로 비추면 "지금 어디"가 위치로 드러난다.
- 후보→대기 이동이 핵심 동작인데 기존엔 두 화면(candidates/done)으로 쪼개져 번거로웠다 → 한 큐 화면 + 탭으로 합쳐 한 화면에서 이동. 주제_큐.md "보류" 섹션도 탭으로 노출(기존 메뉴엔 없었음).
- "실행 이력"과 "진행 중"은 2분할 상세 좌측의 "실행 중/완료" 탭과 같은 상태를 메뉴로 중복 노출 → 실행 1개로 합치고 상태는 화면 탭으로.
- 발행 단위는 채널이 아니라 "글 하나 × 채널 3개(velog·Zenn·LinkedIn)". 채널별 메뉴(zenn/velog)는 실물과 어긋나고 LinkedIn이 빠졌다 → 발행 대기 1화면에서 글별 채널 상태.
- TopBar 워크스페이스 탭과 사이드바 설정 그룹이 2층 중복 → 워크스페이스 제거로 단일화.

## 기각된 대안

- **현재 구성(정보 종류별 분류)**: 레이아웃 스펙 [C]를 옮긴 것. 사용 흐름과 어긋나 "후보→대기" 같은 핵심 동작이 화면 분리로 번거로움. 기각.
- **채널별 발행 메뉴(Zenn 下書き / 벨로그 대기 분리)**: 발행 실물 단위(글×3채널)와 불일치, LinkedIn 누락. 기각.
- **TopBar 워크스페이스 탭 유지(글/설정)**: 사이드바 설정 그룹과 중복, 워크스페이스가 2개뿐이라 층을 하나 더 두는 값이 없음. 기각.
