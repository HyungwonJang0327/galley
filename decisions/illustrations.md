# 본문 삽화 — Galley 산출물에 넣는다 (MVP 리허설 결정)

## 결정

- **본문 삽화를 Galley가 만든다.** 데스크톱 수·토 스케줄 프롬프트 3-1(한국어 삽화)·3-2(일본어 캡션판)가 하던 일을 파이프라인 산출물로 옮긴다. 지금까지 Galley는 본문·Zenn에 삽화 **자리 주석**(`<!-- [삽화] … -->`·`<!-- [挿絵] … -->`)만 남기고 그림은 사람이 데스크톱에서 만들었다.
- 산출물 정의가 바뀐다: `posts/<슬러그>/`의 7개(초안 5종 + evidence.json·verification.json)에 **삽화 N장(`illustN_<한글설명>.png`) + 일본어 캡션판 N장(`illustN_<한글설명>_ja.png`, `.svg` 포함)** 이 더해진다. N은 본문 분량(코드 제외) 2,000자 미만 1 / 2,000~3,000 2 / 3,000 초과 3.
- 스타일은 **소프트 UI v2**(2026-10 확정, blog `tools/make_illust.py`·`illust_example_soft.svg` 기준): 1200×520 SVG, 연한 복숭아 배경(스크립트가 입힘 — SVG에 배경 rect 없음) 위 흰 둥근 카드 + 부드러운 그림자 + 회색 단순 도형 + 빨간 포인트 하나 + 하단 캡션. 예전 남색 팔레트 금지. 사람 얼굴·손 같은 유기적 형태 금지. 회사명·로고·실제 도메인·키·실제 고객 문구·실제 서비스 화면 금지(썸네일과 같은 금지 항목).
- 일본어판은 한국어판 확정 뒤 **글자만** 바꾼다(구도·좌표 동일, monospace 텍스트 유지, 용어는 Zenn판과 맞춤). 넘침은 font-size·줄바꿈·카드 폭으로 고친다.
- 렌더는 Galley의 썸네일과 같은 경로(설치된 Chrome headless, `ThumbnailRenderer` 뒤)로 한다. Playwright·폰트 다운로드를 들이지 않는다(decisions/toolchain-pins.md와 같은 태도 — 새 의존성은 결정 없이 추가하지 않는다).

## 구현 형태(2026-11-19 확정)

- **단계 수 — 7번째 단계 "삽화"**: Zenn 뒤·발행정보 앞. 삽화만 수정 지시로 다시 만들 수 있고, 타임라인에 줄이 따로 생겨 PNG 미리보기·모델 비용이 분리된다. 상태 머신 `STEP_ORDER`·타임라인 6→7줄·재실행 범위 규칙·문서를 함께 고친다. 기각: 발행정보 단계 확장(삽화만 다시 만들 수 없고 한 단계가 모델 호출 여러 번으로 무거워진다).
- **순서 — 썸네일 v2(RH3) → 삽화(RH4) → MR2 ③**: 사용자가 리허설 재실행·승인을 삽화 적용 뒤로 미뤘다(2026-11-19 "삽화 적용 먼저 하고 재실행"). 렌더 경로(Chrome headless)는 이미 있어 삽화를 먼저 할 수도 있었지만, 썸네일·삽화 톤이 맞은 상태로 승인하려고 원래 순서를 지킨다.
- **썸네일 v2 범위 — 오른쪽 그림 조각 포함, PR 두 개**: PR 1은 v2 틀(복숭아 배경·제목 `|` 줄 나누기·마지막 줄 빨강·부제·태그 알약·시리즈 배지, 오른쪽 비움). PR 2는 모델이 쓴 580×630 HTML 조각을 스크립트·외부 주소를 걸러 끼운다. 이 거르기 코드는 삽화 SVG에도 쓴다.
- **일본어 캡션판 — 한국어판과 한 PR**(RH4).
- **검수**: 실행 상세 타임라인에서 PNG 미리보기(지금 썸네일 펼침과 같은 자리). 글자 겹침·잘림은 사람이 보고 수정 지시로 다시 만든다 — 프롬프트의 "Read로 PNG를 열어 확인"은 사람 몫이다.
- **폰트**: Noto Sans KR·IBM Plex Mono는 시스템 설치 전제(다운로드 코드 없음). 없으면 CSS 대체 글꼴로 찍힌다.
- **RH4에서 옮길 원문 규칙**(데스크톱 스케줄 3-1, 2026-11-19 사용자 재전달 — 아직 프롬프트에 없음): 위치 원칙(1장이면 서론의 사건 장면 / 2장이면 서론 + 핵심 설계 결정(보통 "## 1.") / 3장이면 서론 + 핵심 결정 + 삽질·결과 중 하나, 코드 블록 바로 뒤에 두면 "코드에서 본 것을 그림으로 다시 짚는" 흐름) · 다이어그램이 더 맞는 자리(흐름·구조·비교)는 삽화 대신 다이어그램으로 그리되 총 개수는 같다 · 구도는 도형·선·글자로 개념을 은유하는 한 장면 · 공용 defs(`url(#soft)`·`url(#softSm)`·`url(#arr)`·`url(#arrRed)`)와 그림자는 공용 필터만.

## 구현(2026-11-22 RH4 — 사용자 결정 3건 포함)

- **PR 둘**(사용자 결정): ① 파이프라인 삽화 단계 + 타임라인 7줄 ② 승인 시 posts 복사 + 발행정보 삽화 목록 + 실행 상세 PNG 미리보기.
- **개수·파일 이름은 벨로그 본문의 자리 주석을 따른다**(사용자 결정): 삽화 단계는 `<!-- [삽화] illustN_<설명>.png — 여기: … -->` 주석의 이름·개수·자리대로 그린다(최대 3장, 번호는 본문 순서로 다시 매김). 주석이 없는 글만 분량 규칙(2,000 미만 1 / 2,000~3,000 2 / 초과 3)으로 장수를 정하고 모델이 장면·이름을 고른다. 개수·위치 원칙은 본문 단계가 지키도록 `.galley/prompts/velog.md`에 넣었다. 기각: 삽화 단계가 분량 규칙으로 새로 정함(본문·Zenn의 주석 파일명과 어긋날 수 있다).
- **재승인 때 이름이 바뀐 옛 삽화는 `DATA_DIR/replaced/`로 옮긴다**(사용자 결정, PR ②에서 구현): 직전 승인이 쓴 삽화 파일 중 이번 승인에 없는 이름. 지우지 않는다. decisions/topic-slug.md 규칙 4의 옮기는 범위가 "5개 이름"에서 넓어진다 — PR ②에서 그 문서와 CLAUDE.md §5를 함께 고친다. 기각: 그대로 남겨 둠(posts에 옛 삽화가 섞인다).
- **단계 구성**: 입력은 벨로그 본문·Zenn 기사(+수정 지시)뿐 — 근거 번들·리포 경로는 프롬프트에 가지 않는다. 모델 2회(한국어 SVG N장 → 글자만 일본어로, 용어는 Zenn 기사). 출력은 `===ILLUST n: 설명===` 구분 줄 + SVG(JSON에 넣지 않는다). Chrome 확인은 모델 호출 전에. 번호가 하나라도 빠지면 재시도 가능 실패, 잘리면 재시도 불가 실패.
- **산출물(DATA_DIR)**: `illustN.svg`·`illustN.png`·`illustN_ja.svg`·`illustN_ja.png`(번호 고정 이름) + `illustrations.json`(번호 → posts 파일 이름 줄기·자리). posts 이름(`illustN_<설명>.png` 등)은 승인 때 목록에서 붙인다.
- **렌더**: `ChromeIllustrationRenderer` — 썸네일과 같은 `screenshotHtml`(설치된 Chrome). 페이지가 배경·글꼴·공용 defs를 입히고 SVG는 `sanitizeMarkup` + CSP(스크립트 0개).
- **옛 6단계 Run**: 그대로 읽힌다(타임라인의 삽화 줄은 "대기", 이력의 완료 수는 6/7). 승인은 삽화 없이 된다(PR ②). 발행정보부터 재실행만 거절된다.
- **스케줄 3-1에서 옮긴 것**: 위치 원칙·다이어그램 대체는 벨로그 어투와 삽화 프롬프트에, 은유 구도·공용 defs·팔레트·금지 항목은 삽화 프롬프트에. "Read로 PNG를 열어 확인"은 사람 몫(미리보기).

## 이유

- INTENT "기존 수·토 스케줄 대체"(Phase 2 완료 시점)는 스케줄이 만들던 것을 Galley가 다 만들어야 성립한다. 스케줄은 삽화를 만들고 있었다(사용자 2026-11-16 전달 프롬프트 3-1·3-2). 삽화가 빠진 채로는 사람이 글마다 데스크톱으로 돌아가야 해 "파일 수동 편집 0회"가 깨진다.
- 자리 주석까지는 이미 파이프라인이 내고 있어, 그림만 밖에 있는 상태는 반쪽이다.
- 사용자 결정(2026-11-16 "A로, 삽화를 산출물에 넣어").

## 기각된 대안

- **B. 삽화는 계속 사람이 데스크톱에서** — INTENT의 스케줄 대체 목표를 "삽화 제외"로 고쳐야 한다. 사용자가 원치 않음.
- **C. Phase 2로 미룸** — 썸네일 v2와 렌더 경로를 같이 만드는 편이 싸고, 미루면 그 사이 발행하는 글마다 수동 작업이 든다.
