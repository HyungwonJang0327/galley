# ② 파이프라인 실행 위치: 같은 프로세스

## 결정

파이프라인 실행 로직은 전부 `@galley/pipeline` 함수에 둔다. `apps/dashboard`의 Route Handler / Server Action은 그 함수를 **호출만** 한다. Phase 1은 Next.js와 같은 프로세스에서 실행(별도 워커 없음).

## 이유

- 로컬에서 단순·즉시. 별도 프로세스·잡 큐는 Phase 1엔 과설계.
- 로직이 pipeline에 있으면 나중에 워커로 추출하기 쉽다.
- 타임라인 갱신은 폴링 또는 SSE로 — Phase 1-B에서 확정.

## 기각된 대안

- **Route Handler에 실행 로직 직접 작성**: 배포·워커 분리 시 재작성.
- **별도 워커 프로세스 + 잡 큐(지금부터)**: Phase 1 범위 초과 → Phase 2.

## 배포 시 변화

서버리스 실행 시간 제한을 만나면 pipeline 함수를 워커로 추출, 앱은 "실행 시작" 트리거만. 로직 이동뿐이라 비용 낮음.
