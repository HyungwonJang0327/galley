# DB 저장값은 영어, 표시는 한국어

## 결정

**DB 컬럼에 들어가는 값(상태·종류 같은 열거값)은 영어로 저장한다.** 화면에 보이는 한국어는 앱의 라벨 매핑에서 붙인다.

- 예: `Run.status` = `running | pendingApproval | done | failed`, `RunStep.status` = `pending | running | succeeded | failed`, `RunStep.origin` = `fresh | carried`.
- **표시 한국어는 `apps/dashboard`의 라벨 매핑**이 담당한다(`packages/ui`는 도메인을 모르므로 그쪽이 아니다).
- 어휘의 소유자는 그 값을 정의한 모듈이다(실행·단계 어휘는 상태 머신 `stateMachine.ts`).

## 예외 — 사용자 콘텐츠

**사람이 쓴 글과 그 제목은 원문 그대로 저장한다.** 번역·변환하지 않는다.

- 초안 본문·수정 지시 문자열·주제 제목(`Run.topicTitle`)·큐 항목 제목·후보 카테고리 소제목 등.
- 파일 형식이 한국어인 것도 그대로 둔다 — `주제_큐.md`의 섹션 머리글(`## 대기` 등)은 파일 형식이므로 파서·라이터는 한국어를 그대로 읽고 쓴다. **파일 → DB 경계에서 영어로 옮긴다.**

## 이유

- 값이 코드·URL·로그·쿼리에 그대로 나타난다. 한국어 값은 인코딩·정렬·grep·URL 파라미터에서 다루기 번거롭고, 표시 문구를 바꾸면 저장된 데이터까지 바꿔야 한다.
- **표시 문구와 저장값이 분리되면 문구를 자유롭게 고칠 수 있다** — "완료"를 "검수 완료"로 바꾸는 데 마이그레이션이 필요 없다.
- 이미 영어로 굳은 값들과 일관된다: `workerState`(queued/running/interrupted) · 단계 이름(`evidence`/`velog`/…) · 모델 어댑터 id(`anthropic:claude-opus-5`) · 큐 탭 URL(`?tab=waiting`).

## 기각된 대안

- **한국어 저장 + 그대로 표시**: 매핑이 없어 당장 단순하지만, 표시 문구를 바꿀 때마다 데이터 마이그레이션이 필요하고 값이 URL·로그에서 인코딩된다.
- **양쪽 저장(코드값 + 라벨 컬럼)**: 라벨이 행마다 중복되고 어휘가 두 곳으로 갈린다.
