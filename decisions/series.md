# 시리즈 표기: 파일 태그 `[A-1]` + 후보 정의 줄 `시리즈 A.`

## 결정

시리즈는 **`주제_큐.md`의 표기로만 존재한다** — 편 줄 맨 앞의 태그 `[A-1]`과 후보 섹션 `### 시리즈` 소제목 아래의 정의 줄 `시리즈 A. <시리즈명> (<메모>)`. DB에는 `QueueItem.seriesKey`·`episodeNo` 두 컬럼만 두고(파일에서 재생성되는 캐시), **시리즈명·편 목록은 매 적재 때 파일에서 다시 만든다**. 별도 `Series` 테이블은 없다.

- 키는 알파벳 한 글자(`A`), 이름은 정의 줄의 텍스트. **키와 이름을 분리**한다 — 이름을 고쳐도 이력(편 번호·Run)에 영향이 없어야 한다.
- 글쓰기 3단계(벨로그·링크드인·Zenn)와 발행정보는 `StepContext.series`(편 번호·시리즈명·이전/다음 편)를 받는다. 시리즈 안내 줄은 **코드가 붙인다**(형식이 고정이고 링크 치환이 필요하다). 어투 파일에는 시리즈 문구를 넣지 않고, SYSTEM 머리에 서술 지시 한 줄만("이 글은 <시리즈명> N편이다. 이전 편 내용은 한두 문장으로만 요약하고 시리즈 소개·목차는 넣지 않는다").
- 스케줄 프롬프트(월·수·금 자동 초안)가 같은 규칙으로 같은 파일을 읽는다. **파일이 진실이고 두 실행 경로가 같은 결과를 내야 한다**(decisions/queue-sync-direction.md).

## 이유

- 큐 파일은 사람이 직접 편집하고 스케줄 프롬프트도 같은 파일을 읽는다. 진실을 둘로 만들지 않는다.
- 편 줄은 후보 → 대기 → 완료로 옮겨 다닌다. 소속을 줄 자체가 들고 다녀야(태그) 어느 섹션에서든 시리즈를 안다.
- 시리즈명은 바뀔 수 있다(가제 → 확정). 키(알파벳)만 안정적이면 편 번호·Run 이력은 그대로다.

## 기각된 대안

- **`Series` 테이블 + 화면 편집**: 진실이 둘이 되고 스케줄 실행과 어긋난다. 편집은 파일에서 손으로(비목표).
- **태그 대신 `### 시리즈명` 소제목으로 묶기**: 편 줄이 대기로 옮겨지면 소속을 잃는다(카테고리가 후보를 떠나면 사라지는 것과 같은 파일 형식의 한계).
- **제목에 "N편"을 사람이 직접 쓰기**: 편 번호를 재정렬하면 제목을 전부 손봐야 하고, 산출물의 "N편" 문구와 어긋난다.

## 문법

### 편 줄 태그

- 정규식 `^\[([A-Z])-([1-9]\d?)\]\s+` — **제목 맨 앞에만** 인정. 본문 중간의 `[A-1]`은 태그가 아니다. 편 번호는 1~99이고 `[A-0]`·`[A-01]`은 태그가 아니다(앞자리 0을 받으면 되쓰기에서 `[A-1]`로 바뀐다 — BX1 리뷰 L2).
- 대기·후보·보류·완료 어느 섹션에나 올 수 있다. 완료 줄은 `- YYYY-MM-DD [A-1] <글 제목> (posts/<슬러그>)` — 날짜 다음에 태그.
- 파서는 태그를 떼어 `QueueTopic.series = { key, episode }`에 넣고 `title`은 태그 뺀 원문으로 둔다. 라이터는 태그를 다시 앞에 붙인다(완료 줄은 날짜 → 태그 → 제목 순). 이동(`moveTopic`)·재정렬은 `series`를 그대로 들고 간다.
- 태그는 **매칭 키(`normalizeTopicTitle`)·표시 제목·프롬프트 제목(`stripTopicHints`)·슬러그 어디에도 들어가지 않는다**. 매칭 키에서 빼도 태그 없는 기존 제목의 키는 변하지 않는다(테스트로 고정). 제목에 태그를 포함해 이미 적재된 기존 DB 행은 양쪽을 같은 함수로 정규화하므로 새 키에 그대로 매칭돼 id가 유지된다(제목 컬럼만 태그 없는 값으로 갱신).
- 태그 바로 뒤 `(기존 글)` 메모가 있는 편은 **이미 발행된 글**이다(`alreadyPublished`). 실행 대상에서 제외한다 — 큐 화면 실행 버튼 비활성 + 사유 표시, 단계에 들어오면 `SERIES_EPISODE_ALREADY_PUBLISHED`(재시도 불가). `(기존 글)`은 괄호 힌트(키워드)로 세지 않는다.
- 차단 위치(2026-09-25 사용자 결정, BX3 리뷰 M5): **워커가 모든 단계의 시작에서** 편 정보를 한 번 읽고 `(기존 글)`이면 모델을 부르기 전에 `SERIES_EPISODE_ALREADY_PUBLISHED`(재시도 불가) — 근거 수집 비용이 나가지 않고, 재실행이 링크드인·Zenn부터여도 막힌다. 대시보드는 큐 화면에 실행 버튼이 아직 없어(BS5 뒤) 행 ⋮ "지금 실행"의 비활성 사유 "이미 발행된 글입니다."로 표시한다(2026-09-26 사용자 결정, BX5) — 실행 버튼이 생겨도 같은 판정(`QueueRowSeriesView.alreadyPublished`)을 쓴다.

### 정의 줄

- 정규식 `^시리즈 ([A-Z])\.\s+(.+?)(?:\s*[(（](.*)[)）])?\s*$` — **후보 섹션의 `### 시리즈` 소제목(`^###\s+시리즈`) 아래에서만** 인정. 다른 소제목 아래의 `시리즈 A.` 줄은 정의로 보지 않고 무시한다(현행 동작 유지).
- `- `로 시작하지 않는 줄이라 지금 파서는 버린다 → **되쓰기 한 번에 정의 줄이 사라진다.** 이것이 BX1의 첫 테스트다. 파서는 `ParsedQueue.seriesDefs: { key, name, note?, category, position }`로 읽고, 라이터는 **같은 자리**(후보 배열에서 `position`번째 항목 앞, 마지막이면 끝)에 되돌린다. 정의 줄 앞에는 빈 줄 하나(현재 파일의 모양 그대로 — 픽스처 라운드트립은 바이트 동일).
- 편 줄이 전부 대기로 옮겨진 뒤에도 정의 줄은 후보에 남는다(예: 시리즈 D). 정의 줄만 있고 편이 없는 시리즈도 유효하다.
- 괄호는 메모다. 리포·기간 힌트와 같은 규칙으로 `topicHints`에 넘길 수 있지만 이번에는 **보존만** 한다. 단 `ja: <일본어 표기>` 항이 있으면 Zenn 단계가 시리즈명의 일본어 표기로 쓴다(없으면 한글명 그대로) — 아래 "확정 사항" 2.

### 완료 줄의 벨로그 URL

- 이전 편 링크에 쓴다. 완료 줄(또는 `(기존 글)` 편 줄)에 `https://velog.io/...`가 있으면 그것, 없으면 자리표시자 `[벨로그 링크]`. URL 문자에 닫는 괄호는 넣지 않는다 — 괄호 안에 쓴 URL은 줄 끝 URL이 아니다.
- 위치는 **괄호 밖 줄 끝**(아래 "확정 사항" 1). **URL은 매칭 키·괄호 힌트(키워드)에서 제외**한다 — 나중에 URL을 붙여도 그 완료 항목이 "사라진 줄 + 새 줄"로 갈라지지 않게. 줄 끝 URL은 완료 줄뿐 아니라 **모든 섹션**에서 매칭 키·표시 제목에서 뗀다(대기 줄 끝에 참고 URL을 붙여도 같은 항목 — BX1 리뷰 L4).
- **한계(현행 유지, 2026-09-24 사용자 결정)**: 태그를 키·슬러그에서 빼므로 다른 시리즈에 같은 제목(`[A-1] 소개`·`[B-1] 소개`)이 있으면 한 항목·같은 슬러그가 된다. 편 제목을 서로 다르게 쓰는 것으로 피한다(BX1 리뷰 M1).

## 산출물 형식 (스케줄 프롬프트 1-1절과 동일)

- **벨로그 본문**: `# 제목` 바로 아래 인용 줄 `> <시리즈명> 시리즈 N편. [이전 편: <제목>](<링크>)` — 1편은 `> <시리즈명> 시리즈 1편.`. `## 결과` 절 끝(다음 H2 또는 EOF 앞)에 `다음 편: <제목>` — 마지막 편은 생략. 링크는 완료 항목에 벨로그 URL이 있으면 그것, 없으면 `[벨로그 링크]`. 둘 다 코드가 붙인다(모델 출력 뒤 후처리).
- **발행 제목에 편 번호** (결정 변경 2026-09-25 사용자 확정, 처음 제기 BX1 리뷰 M1): 벨로그 `# <제목> | <시리즈명> N편`, Zenn frontmatter `title: "<제목> (第N回)"`. 위 인용 줄·はじめに 문장과 **함께** 쓴다. 붙이는 것은 코드(모델이 이미 붙였으면 떼고 한 번만) — 큐 파일 제목에 사람이 "N편"을 쓰는 안(기각된 대안)과 다르다. 모델 출력에 H1이 없으면 제목 접미사는 빠진다(알려진 한계, BX3 리뷰 L3). **스케줄 프롬프트 1-1절에도 같은 표기를 반영해야 두 실행 경로가 같다 — Galley 밖(사용자 몫), 미결.**
- **링크드인**: 시리즈 언급 없음. 입력 본문에서 **이 시리즈의** 표기(제목 접미사·첫 H2 앞 인용 줄·결과 절 끝/본문 끝 `다음 편:`)만 떼고 모델에 넘긴다 — 다른 이름·다른 위치의 비슷한 줄은 보존(BX3 리뷰 M1·L2).
- **Zenn**: 같은 제거 뒤, `## はじめに` 첫 문장 앞에 「<시리즈명(ja)>シリーズの第N回です。」를 코드가 붙인다. 절 첫 내용이 확실한 문단이 아니면(Zenn 블록 `:::`·링크 카드 URL·`@[card]`·`$$`·HTML·이미지·목록·코드) 소제목 아래 새 문단으로(BX3 리뷰 M4).
- **발행정보**: `## 벨로그 시리즈` 절에 `시리즈명 · N/M편`(M = 파일에 있는 그 시리즈 편 수). 시리즈 아니면 절 없음. 편 번호가 비연속(1·2·5)이면 `5/3편`이 나오지만 M은 편 수 그대로 둔다(BX4 리뷰 L4, 사용자 유지 결정).
- **완료 이동**: 태그를 유지해 `- YYYY-MM-DD [A-1] <글 제목> (<메모>, posts/<슬러그>)` — 메모는 선택(없으면 `(posts/<슬러그>)`), 있으면 posts 항 앞에 쉼표로(실제 파일의 `2023 글 리라이트, posts/…`와 같은 모양). 완료 섹션 **맨 끝**에 붙인다(날짜 오름차순이 실제 파일 모양, 백데이트 입력이어도 정렬하지 않음 — 줄 순서 보존). 글 제목·메모는 한 줄, 메모에 괄호 금지, 글 제목 맨 앞이 태그·`(기존 글)`이면 거부(`INVALID_COMPLETION`, BX4 리뷰 H1·M1·L1). **완료 줄 제목이 큐 제목과 다르면 매칭 키가 달라진다** — 호출부가 파일을 쓰기 전에 QueueItem 행(title·status·completedOn)을 먼저 맞춰야 재적재에서 행이 갈라지지 않는다. **확정(2026-09-26 B3a)**: `approveAndPublishRun`이 한 트랜잭션에서 QueueItem을 `completedTitle`(= `<글 제목> (posts/<슬러그>)`)·`완료`·`completedOn`·완료 섹션 끝 order로 갱신하고 Run을 done으로 만든 뒤 마지막에 큐 파일을 쓴다 — 재적재는 `normalizeTopicTitle`(힌트·태그 제거) 키 + 같은 섹션 우선 매칭이라 같은 행에 붙는다(테스트: 시리즈 편 seriesKey·episodeNo 보존). 메모(`note`)는 아직 넣지 않는다.
- **발행 체크리스트**(시리즈 편만, 화면은 Phase 2): "벨로그 시리즈에 추가" · "이전 편 링크 자리표시자 채움".

## 데이터 흐름

파일 표기 → 파서(`QueueTopic.series`, `ParsedQueue.seriesDefs`) → 적재(`QueueItem.seriesKey`·`episodeNo`) → 워커가 `getSeriesContext(seriesKey)`로 `StepContext.series`를 채움 → 단계가 안내 줄 삽입/제거 → 발행정보 절 → 완료 줄 태그 유지.

**`getSeriesContext`는 읽기 전용이다** (결정 변경 2026-09-24 사용자 결정, BX2 리뷰 H1 — 처음엔 "편 목록은 DB 세 상태"):

- 파일을 **한 번** 읽어 이름·`ja:`(정의 줄)와 **편 목록(편 줄)**을 얻는다. DB는 편 줄 → `QueueItem.id` 조회에만 쓴다(적재와 같은 매칭 — 정규화 제목, 같은 섹션 우선). 아직 적재 안 된 새 줄은 `topicId`가 없다.
- **적재하지 않는다.** 워커가 부르는데 `importChain`은 한 프로세스 안에서만 적재를 줄 세운다 — 대시보드 적재와 겹치면 같은 줄이 두 행이 된다. 적재는 대시보드 몫 그대로.
- 편 = 파일에 있는 그 시리즈 편 줄 **네 섹션 전부** — 직접 보류한 편도 센다(편 번호·M이 어긋나지 않게, 사용자 결정). 파일에 없는 DB 행(사라진 줄·완료 Run으로 남은 행)은 세지 않는다. 편 번호순, 겹치면 파일 순서.
- 슬러그(`(…, posts/<슬러그>)` — 괄호 시작·쉼표 뒤 항만)와 줄 끝 URL은 **발행된 편**(완료 줄, 또는 어느 섹션이든 `(기존 글)` 편)에서만 읽는다. 이전 편 링크로 쓰는 URL은 `velog.io`만 — 아니면 자리표시자.
- `(기존 글)` 판정은 맨 앞 괄호의 첫 항(`(기존 글, 2025)` 포함) — 힌트 파서가 키워드에서 빼는 기준과 같은 함수(`isAlreadyPublished`). `ja:`는 전각 콜론 `ja：`도 받는다.
- 정의 줄이 없는 키는 `SERIES_NOT_DEFINED`(값) — 이름을 지어내지 않는다.
- 워커 조회(`WorkerDeps.series`, 2026-09-25 BX3 리뷰 사용자 결정): 단계 시작에 한 번(재시도끼리는 같은 값). 실패 분류 — 정의 줄 없음 `SERIES_NOT_DEFINED` · DB에는 시리즈 편인데 파일 편 줄과 짝이 안 맞음 `SERIES_EPISODE_NOT_MATCHED`(표기 없는 본문을 조용히 내지 않는다) · 워커에 BLOG_DIR 없음 `SERIES_SOURCE_UNCONFIGURED`(시리즈 편만, 아닌 주제는 그대로) · 큐 파일 못 읽음 `SERIES_QUEUE_UNREADABLE` — 여기까지 재시도 불가 · DB 일시 오류 `SERIES_LOOKUP_FAILED`만 재시도 가능.
- 이전 편 제목·시리즈명은 `stripTopicHints`(괄호 힌트·태그·URL 제거)만 거치고 식별 정보 필터(redact)는 거치지 않는다 — 주제 제목이 프롬프트로 가는 기존 경로와 같은 수준(BX3 리뷰 L8, 사용자 "기록만", todo). 링크 텍스트의 대괄호는 이스케이프.
- 알려진 한계: 이동 한 번에 정의 줄 표기가 정규화되고 괄호가 둘인 이름(`앱 (v2) (메모)`)은 이름·메모가 잘못 갈린다(BX1 리뷰 L1, 미반영) · 사라진 줄 복원이 되붙인 편 번호가 이미 쓰였어도 경고하지 않는다.

## 확정 사항 (2026-09-24 사용자 결정)
