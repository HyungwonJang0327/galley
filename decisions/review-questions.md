# 확인 질문 — 실행이 물을 곳을 골라 묻고, 답을 받은 곳만 고친다 (MVP 포함)

## 결정

- **MVP에 넣는다**(2026-11-22 사용자 "이 기능도 MVP에 포함"). 데스크톱 스케줄이 하던 "글을 뽑고 → 확인이 필요한 2~3군데를 골라 묻고 → 답을 반영해 글을 고친다"를 Galley 안에서 한다. 지금은 `[확인 필요]` 주석·근거 검증 목록·자유 글 수정 지시라는 재료만 있고, 추리기·답 입력·부분 수정이 없다.
- **질문은 규칙으로 고른다**(모델 호출 없음). 기각: 모델이 고름(실행당 호출 1회 추가), 본문 단계가 같이 냄(근거 검증 결과가 반영되지 않는다).
- **답은 이전 본문을 주고 그 부분만 고친다.** 기각: 지금처럼 전체를 다시 씀(답하지 않은 문장까지 달라진다).

## 질문 고르기

- 본문 프롬프트에 주석 형식을 고정한다: `<!-- [확인 필요] <사용자에게 물을 질문 한 문장> — <왜 확인 못 했는지 한 줄> -->`. 질문 추출은 이 형식을 파싱해 **앞부분(질문)만** 쓴다.
- 우선순위: `[확인 필요]` 주석 → 근거 검증의 "근거 없음" 주장. 같은 종류 안에서는 본문 순서.
- 상위 3개만 질문으로 올린다. 넘치는 것은 버리지 않고 **"그 외 N건"으로 접어** 같이 보여 준다.
- 질문마다 **앵커**(주석이 있던 문단 — 근거 없음 주장은 그 문장의 문단)를 같이 저장한다. 답 반영이 쓴다.

## 답 반영

- 답 종류는 셋: **채움 / 모름(현행 유지) / 삭제(그 문장 빼기)**.
  - 모름: 모델 호출 없이 주석만 제거하고 확정한다.
  - 삭제: 코드로 처리한다(모델 호출 없음).
  - 채움: 모델을 부르는 유일한 경우.
- 채움은 **이전 본문 전체 + 질문·답 + 앵커**를 주고 전체 본문을 다시 출력하게 한다. 받은 뒤 이전 본문과 **문단 단위 diff**를 떠서, 바뀐 문단이 앵커 문단과 그 앞뒤 1문단 밖에도 있으면 실패 → 1회 재시도 → 또 실패하면 승인 대기로 올린다.
- 이 diff 검사는 **승인 게이트 모듈 쪽**에 두고 단위 테스트를 붙인다.
- 뒤 단계는 영향 있는 것만:
  - 근거 검증은 항상 재실행.
  - 링크드인·Zenn은 전체 재생성이 아니라 **이전 결과 + 바뀐 문단**을 주고 같은 방식(패치 + diff 검사)으로 고친다.
  - 삽화·썸네일은 기본 건너뛴다. 바뀐 문단이 `[삽화]` 주석 바로 앞뒤일 때만 "삽화 다시 만들까요?"를 확인 질문으로 올린다.
- "이전 산출물을 입력으로 받는 단계"는 todo RH5(재실행 입력에 이전 본문을 넣을지)와 같은 변경이다 — **RH5를 이 작업(RH13)에 합쳐 닫는다.**

## 진행 방식

- 작업 단위 하나가 끝날 때마다 커밋 → /log → 보고 → 다음 진행 여부를 묻고 멈춘다(CLAUDE.md §9 그대로).

## 착수 전에 정할 것(에이전트 메모 — 결정 아님)

- 재실행 규칙은 "시작 단계 + 이후 전부"(decisions/evidence-collection.md)다. 삽화·발행정보를 건너뛰려면 **뒤 단계를 carried로 두는 길**이 상태 머신에 필요하다 — 지금 carried는 시작 단계 앞에만 있다.
- 발행정보의 소개·태그·썸네일 제목은 본문에서 나온다. 썸네일을 건너뛰면 발행정보 글도 이전 것이 남는다 — 건너뛰는 범위가 "썸네일 PNG만"인지 "발행정보 단계 전체"인지.
- 채움이 두 번 실패해 승인 대기로 올릴 때 본문은 이전 본문 그대로인지(답 미반영 표시와 함께), 실패한 출력을 보여 줄지.
- 문단의 정의(빈 줄로 나눈 덩어리, 코드 블록·표·주석 줄의 취급)와 앵커를 어디에 저장할지(DATA_DIR 산출물 파일 / DB).
- 모름·삭제만 있는 답이면 본문이 코드로만 바뀐다 — 이때도 근거 검증·링크드인·Zenn 패치를 도는지.
