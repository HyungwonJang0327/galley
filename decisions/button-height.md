# Button 높이 — md를 폼 컨트롤(32)에 맞추고 lg(36) 추가 (RF-22b)

## 결정

- `--ui-button-height-md`를 **32px**(= `--ui-control-height`)로 내린다. 기본 size `md` 버튼은 Input·Select 트리거와 같은 줄에 놓이면 그대로 줄이 맞는다.
- **`size="lg"`(36px, `--ui-button-height-lg`)를 추가**한다 — 혼자 서는 주요 CTA용. 앱은 필요한 자리에서만 명시한다.
- `sm`(28px)은 그대로 — 목록 행·표 안의 밀집 액션용.

## 이유

- 토큰 주석에 "폼 컨트롤(32)보다 크다 — 나란히 놓일 때의 통일은 P7"로 미뤄 둔 것을 닫는다.
- 실제 섞이는 자리가 있다: 실행 상세 ActionBar(Select 32 옆 버튼), 큐 근거 편집 Dialog(Input 32 + 제출 버튼 36). `align-items: center`로 가운데만 맞춰 두면 한 줄 안에서 높이가 들쭉날쭉하다.
- "필드 옆은 sm" 같은 규칙은 사람이 기억해야 하고, sm은 28이라 32에도 안 맞는다. 기본값이 맞는 쪽이 규칙이 없는 쪽이다.
- 36이 필요한 자리는 소수(홈의 주요 실행 버튼 정도)라 옵트인(lg)이 맞다.

## 기각된 대안

- **sm을 32로(md 36 유지)** — ActionBar는 바로 맞지만 28이 사라져 밀집 행(큐 행 메뉴·홈 카드 등 7곳)이 커진다.
- **현행 유지 + 문서화** — 높이 차이를 의도로 적는 것인데, Input+Button 한 줄은 계속 들쭉날쭉하고 토큰 주석의 "P7에서 통일"이 영구 보류가 된다.

## 배포 시 변화

- 모든 md 버튼이 4px 작아진다(Dialog footer·PageHeader 액션 등). `lg` 추가는 공개 API 확장 → **minor**.
- verify-layout에 버튼 높이 단언은 없다(2026-11-15 확인). 갤러리 size 행에 lg를 추가한다.
