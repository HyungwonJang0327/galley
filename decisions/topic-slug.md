# 주제 슬러그 — 파생·승계·재승인

## 결정

슬러그(`Run.topicSlug`)는 **주제당 한 번 정해지고 이후 그 주제의 모든 실행이 이어받는다.** 네 규칙으로 나눈다.

1. **파생 입력은 힌트를 뗀 제목이다.** `topicSlug(stripTopicHints(title))` — 시리즈 태그·줄 끝 URL·괄호 묶음(리포 별칭·기간·`posts/…`)을 뗀 제목에서 만든다. `무한 스크롤 (spacehome)` → `무한-스크롤`. 본문·발행정보 제목이 힌트를 떼는 것(BS2 리뷰 2)과 같은 규칙이다.
2. **같은 주제의 다음 실행은 슬러그를 승계한다.** `startRun`은 그 주제(`topicId`)에 **승인된(done) Run이 있으면 그중 가장 최근 것**, 없으면 가장 최근 Run의 `topicSlug`를 그대로 쓴다(⚠️ 2026-09-27 TS2 리뷰에서 "가장 최근 Run"을 "승인된 Run 우선"으로 — 갱신 이력). 실행 기록이 없으면 제목에 적힌 산출물 위치 `(posts/<슬러그>)`를 쓰고, 그것도 없으면 제목에서 만든다(규칙 1). 수정 지시 재실행(`startRerun`)은 지금처럼 직전 Run 것을 복사한다. 결과: **한 주제의 Run은 슬러그가 같고 posts 폴더는 하나다.**
3. **완료된 주제는 실행하지 않는다.** `startRun`이 상태가 완료인 주제를 `TOPIC_ALREADY_DONE`으로 거절한다(전에는 6단계가 다 돌고 승인에서야 막혔다). 다시 쓰려면 먼저 되돌린다 — 아래 "되돌리기 절차". 같은 이유로, **실행 기록이 없는 주제의 슬러그를 다른 주제의 승인된 실행이 쓰고 있으면 `SLUG_TAKEN`으로 실행 전에 거절한다**(2026-09-27 TS3 — 절차를 어긴 되돌리기와 힌트 뗀 제목이 같은 두 주제).
4. **재승인은 직전 승인이 쓴 파일만 지우고 덮어쓴다.** 같은 폴더에 다시 승인할 때, 직전 승인 Run의 글 제목으로 만든 5개 이름(`<제목>.md`·`_링크드인.md`·`_zenn.md`·`_발행정보.md`·`_썸네일.png`)을 지운 뒤 새 7개를 쓴다. 직전 글 제목은 DATA_DIR의 그 Run `publish.md`에서 읽는다(사실 기록). 못 읽으면 지우지 않는다. 그 밖의 파일은 건드리지 않는다.

### 되돌리기 절차 (수동)

완료 주제를 다시 쓰려면 `주제_큐.md`에서:

1. 완료 섹션의 그 줄을 대기(또는 후보) 섹션으로 **옮긴다**(복사하지 않는다 — 완료에 남기면 재승인 뒤 같은 완료 줄이 둘이 되고 Run 없는 완료 행이 생긴다).
2. **앞의 날짜만 뗀다.** `(posts/<슬러그>)`와 줄 끝 URL은 그대로 둔다 — 매칭 키에는 영향이 없고, posts 표기는 실행 기록이 없을 때 슬러그로 읽히며(규칙 2), URL은 재승인한 완료 줄이 이어받는다.
3. **제목은 고치지 않는다.** 고치거나 날짜를 남기면 줄 텍스트 매칭이 끊겨 새 주제가 된다(queue-sync-direction "알려진 한계") — 그 실행은 `SLUG_TAKEN`으로 거절된다.
4. 리포 이름·키워드 힌트를 다시 적으려면 **기존 `(posts/…)` 괄호 안에 쉼표로** 덧붙인다(`(posts/feed-model, spacehome)`). 완료 줄에는 원래 힌트가 없어 그대로 두면 근거 자동 연결이 0건이다. **줄 끝 URL 뒤에 새 괄호를 쓰지 않는다** — URL이 줄 끝이 아니게 되어 매칭 키에 섞이고 새 주제가 된다.
5. 큐를 다시 불러온다("파일에서 다시 불러오기") → 같은 주제로 붙는다 → 실행 → 승인하면 같은 폴더를 덮어쓴다.

대시보드의 "다시 쓰기" 버튼(완료 탭에서 되돌리기)은 만들지 않았다 — todo에 보류로 둔다.

## 이유

- **리포 별칭이 밖으로 나간다.** 슬러그가 힌트째 만들어져 posts 폴더 이름·`주제_큐.md` 완료 줄·발행정보 `## URL 슬러그`에 `spacehome` 같은 별칭이 들어간다. 모델 입력에서 힌트를 뺀 이유(BS2)와 같은 축의 노출이다.
- **힌트만 고쳐도 폴더가 갈린다.** `(spacehome)` → `(spacehome, react-router)`는 같은 주제(매칭 키는 힌트를 뗀다)인데 슬러그는 달라진다. 연결(TopicAnalysisLink)을 topicId로 바꾼 이유(evidence-collection 2026-09-21)와 같다.
- **재승인이 새 폴더를 만든다.** 승인 뒤 DB 제목은 `<글 제목> (posts/<슬러그>)`가 된다. 되돌려 실행하면 슬러그가 `<글-제목>-posts-<옛-슬러그>`로 길어지고, 반복할수록 더 길어진다(80자에서 잘림). 옛 폴더는 남고 완료 줄의 경로가 바뀐다.
- **슬러그는 키가 아니라 사실 기록이다**(queue-sync-direction 2026-09-12). 그러면 기록은 한 번 정해진 뒤 같은 주제 안에서 바뀔 이유가 없다 — 승계가 그 결정의 자연스러운 귀결이다.
- **완료 주제 실행은 비용만 쓴다.** 승인이 `TOPIC_NOT_IN_QUEUE(완료)`로 거절할 것을 실행 전에 안다.
- **옛 이름 파일이 남으면 폴더가 거짓말을 한다.** 글 제목이 바뀐 재승인 뒤 옛 본문·옛 썸네일이 새 것과 섞여 어느 것이 발행본인지 알 수 없다. 지우는 대상을 "직전 승인이 쓴 것으로 확인되는 이름"으로 좁혀 CLAUDE.md "기존 파일을 덮어쓰지 않는다"와 부딪히지 않게 한다.

## 따라오는 것

- **한 재실행 사슬의 슬러그는 같다**는 성질이 주제 전체로 넓어진다. 단계·승인·대시보드 미리보기는 "현재 Run의 슬러그 + 출처 Run id"로 파일을 찾는데(artifacts·evidence 경로), 이 조합이 어긋나는 경우(B2e·BE13 리뷰 L7)는 규칙 2 뒤에도 생기지 않는다. **`startRerun`이 슬러그를 다시 계산하도록 바꾸면 그 모든 지점이 깨진다** — 바꾸지 않는다.
- 덮어쓰기 규칙(run-execution-model §1 "DB에 같은 주제·같은 슬러그의 done Run이 있을 때만")은 그대로다. 규칙 2로 재승인 Run의 슬러그가 직전과 같아져 이 규칙이 실제로 동작한다.
- 완료 줄의 `posts/<슬러그>`가 재적재에서 **키워드로 들어가던 것**을 막는다(힌트 추출에서 `posts/`로 시작하는 토큰 제외).

## 알려진 한계

- **이미 기록된 슬러그는 바꾸지 않는다.** 규칙 1 전에 실행한 주제는 힌트가 든 슬러그를 계속 승계한다(posts 폴더가 이미 그 이름일 수 있다). 마이그레이션 없음.
- **힌트를 뗀 제목이 같은 두 주제는 슬러그가 같다**(예: 같은 제목에 리포만 다른 두 줄). 둘째 주제의 승인은 `POSTS_DIR_EXISTS`로 거절되고 사람이 제목을 구분해야 한다. 시리즈의 같은 한계(series.md)와 같은 처리 — 현행 유지.
- **파일에서 제목을 고쳐 되돌리면 새 주제**가 된다. 새 주제는 이전 Run이 없어 제목에서 슬러그를 만들고, 폴더가 이미 있으면 `POSTS_DIR_EXISTS`다. 절차 3을 지킨다.
- 직전 승인 Run의 `publish.md`가 DATA_DIR에 없으면(옛 Run·DATA_DIR 정리) 옛 이름 파일은 남는다.
- **가드는 DB에 적재된 상태를 믿는다.** 파일에서는 완료인데 재적재 전이면 실행이 통과하고 승인에서 `TOPIC_NOT_IN_QUEUE`다. 파일에서 줄이 사라진 행(완료로 남은 행·자동 보류 행)은 되돌릴 줄이 없다 — 실행 직전 재적재 여부는 실행 Dialog(BM6)에서 정한다. 수정 지시 재실행(`startRerun`)에는 완료 가드가 없다(승인 대기 중 파일에서 완료로 옮겨진 드문 경우).
- **재승인하면 다시 적은 힌트는 완료 줄에서 빠진다**(첫 완료와 같다 — 완료 줄은 글 제목·posts·URL만). 태그와 URL은 유지된다.
- **옛 슬러그는 URL 슬러그로도 계속 나간다.** 힌트가 든 슬러그를 승계한 주제는 새 실행의 발행정보 `## URL 슬러그`에도 별칭이 실린다. 글 제목이 바뀌어도 URL 슬러그는 첫 실행 기준이다 — 발행할 때 사람이 고친다.
- **Run을 지우면 승계할 기록이 사라진다**(시드·DB 초기화). 그때는 제목의 `(posts/<슬러그>)`를 읽어 기존 폴더와 같은 슬러그를 쓰지만, 그 주제에 승인된 Run이 없으므로 승인은 `POSTS_DIR_EXISTS`다 — 덮어쓰기 규칙은 DB 기록만 믿는다. 폴더를 옮기거나 지운 뒤 승인한다.
- **한 번도 승인되지 않은 주제도 슬러그가 고정된다.** 같은 주제로 남는 제목 변경은 힌트·시리즈 태그·줄 끝 URL 수정과 승인이 바꾸는 완료 제목뿐이라(본문을 고치면 새 주제) 범위는 좁다.
- **같은 주제에 실행 요청이 동시에 오면 attempt가 중복될 수 있다**(기존 경쟁 — `startRun`은 트랜잭션이 아니고 `(topicId, attempt)`는 unique가 아니다). 슬러그는 갈리지 않는다. 로컬 단일 사용자라 제약 추가(마이그레이션)는 하지 않았다.
- **제목 본문의 괄호도 빠진다.** 뗀 범위가 매칭 키(`normalizeTopicTitle`)와 같아서 `useEffect(의존성 배열) 정리` → `useeffect-정리`다. 키가 같은 제목끼리만 슬러그가 같으므로 새 충돌은 없다.
- **닫히지 않은·중첩 괄호는 별칭이 남는다**(`제목 (spacehome` → `제목-spacehome`). `stripTopicHints`를 고치면 매칭 키가 바뀌어 기존 행 매칭에 영향이 가므로 여기서 다루지 않는다 — todo TD8과 같은 뿌리. 줄 끝 URL이 괄호 앞에 오는 줄(문서화된 형식이 아님)도 URL이 남는다.
- **힌트뿐인 제목은 실행하지 않는다**(`(spacehome)` — 힌트를 떼면 빈 제목). `startRun`이 `EMPTY_TITLE`로 거절한다(2026-09-27 TS1 리뷰, 사용자 결정). `slugForTopicTitle` 자체의 폴백은 `topic`.

## 기각된 대안

- **힌트 포함 유지**: 같은 제목·다른 리포를 슬러그로 구분할 수 있지만 별칭 노출과 힌트 수정 시 분기를 그대로 둔다.
- **매 실행 제목에서 다시 파생**: 규칙 1만으로는 완료 줄의 글 제목이 원래 주제 제목과 다를 때 여전히 갈린다.
- **슬러그를 QueueItem 컬럼으로**: 주제에 슬러그를 저장하면 승계가 조회 없이 되지만 마이그레이션이 필요하고, "Run이 어느 폴더에 썼는가"의 진실이 두 곳이 된다. Run 기록에서 읽는 쪽이 단순하다.
- **대시보드 "다시 쓰기" 버튼을 지금 구현**: 파일 줄 이동·날짜 제거를 코드가 하면 절차 실수가 없지만 범위가 크다. 수요가 생기면.
- **옛 파일을 남김 / 폴더를 비우고 다시 씀**: 남기면 폴더가 섞이고, 비우면 사람이 넣은 파일까지 지운다.
